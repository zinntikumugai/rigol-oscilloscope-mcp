# MHO98 未ライセンス状態 実機検証(Phase 4 事前プローブ)

**実施日:** 2026-08-25
**対象:** RIGOL MHO98(ファームウェア 00.01.00、LAN SCPI :5555)。IP・シリアルは記録しない(`RIGOL_TEST_ADDRESS` 環境変数で指定)
**状態:** バンドルライセンス MHO900-BND **未適用**。ライセンス適用は一方通行のため、本記録は適用後には再現できない
**手順規律:** REPL相当のスクリプトから1コマンドずつ送信 → 応答(5秒timeout)→ `:SYSTem:ERRor?` → 記録。沈黙時はソケット再接続(open時空行送信)→ `*IDN?` で復旧確認。リスク昇順で実施し、`*OPT?` は送信しない(理由は5章)

## 1. オプション照会(`:SYSTem:OPTion:STATus?` / `:VALid?`)

MHO900プログラミングガイド 3.24.18/3.24.19 記載の全 `<type>` トークンが正常応答した(エラーキュー全て `0,"No error"`、レイテンシ 0.03〜0.11 s)。

| `<type>` | 応答 | 意味 |
|---|---|---|
| BND(`:VALid?` / `:STATus?` 両方) | **0** | バンドル未適用(期待どおり) |
| AFG100 | 0 | |
| **AFG50** | **1** | **AFG 50MHz 導入済み(工場出荷標準の模様)** |
| AUDio | 0 | |
| CAN-FD | 0 | ハイフン付きトークンをそのまま受理 |
| FLEX | 0 | |
| AERO | 0 | |
| **RLU-05** | **1** | **500Mptsメモリ 導入済み(工場出荷標準の模様)** |
| BWU03T05 / BWU03T08 / BWU05T08 | 0 | |

- `:VALid?`(後方互換形)と `:STATus?`(推奨形)は同一応答。実装は `:STATus?` を採用する
- **注意: 「未ライセンス」でも AFG50 / RLU-05 は 1** — 全て0を前提にした実装・テストは書かないこと

### `<type>` リスト外トークンは沈黙する

`:SYSTem:OPTion:STATus? AUTOA`(CAN-FDオプションの別名として試行)→ **応答なし(SILENT/TIMEOUT)**。ソケット再接続+空行で復旧、`*IDN?` は0.03秒で応答。

→ **未定義ヘッダだけでなく、不正なパラメータトークンでもSCPIサーバーが沈黙する**(プロファイルの `invalid_query_behavior: silent_timeout` と整合)。照会に使うトークンはガイド記載リストに厳密に限定すること。

## 2. `:SYSTem:MODules?`

応答: `1,0,0,0,0` = LA搭載 / DG非搭載。プロファイルの `digital_channels: 16` と整合。AFG50オプションが1である一方DGモジュールは0である点に注意(MODulesは外付けモジュールの搭載状態であり、ライセンスオプションとは別物)。

## 3. `:BUS`(デコード)読み取り系 — 全て正常応答

未ライセンス状態でデコード系SCPIは全て正常に動作した。**ガイドの記載どおり RS232/I2C/SPI/CAN/LIN/Parallel デコードは標準搭載(ライセンス不要)** の実機裏付け。

| コマンド | 応答 |
|---|---|
| `:BUS1:MODE?` | RS232 |
| `:BUS1:DISPlay?` / `:FORMat?` / `:EVENt?` / `:LABel?` / `:POSition?` | 1 / HEX / 1 / 1 / 0 |
| `:BUS4:MODE?` | PAR(バスは4本) |
| `:BUS1:RS232:BAUD?` | 9600 |
| `:BUS1:IIC:ADDBits?` | 7 |
| `:BUS1:SPI:MODE?` | CS |
| `:BUS1:CAN:BAUD?` | 1000000 |
| `:BUS1:LIN:BAUD?` | 9600 |
| `:BUS1:THReshold? TX` | 0.000000 |

書き込みも確認: `:BUS1:MODE PARallel` → readback `PAR` → `:BUS1:MODE RS232` で復元(エラーなし、復元確認済み)。

## 4. オプションゲート済みニモニックの挙動(一方通行データ)

`:BUS1:CAN:FDBaud?`(CAN-FDオプション必須、未ライセンス状態)→ **沈黙せず** 値 `1000000` を返し、エラーキューに `-222,"Data out of range"` を積んだ(レイテンシ0.044 s)。

→ **将来CAN-FD等のオプション機能を実装する際も、送信前ライセンスゲートは不要**。既存の「set → エラーキュー確認 → read-back」パターンで機器自身のエラーが検出できる。ただし「値が返る+エラーも積まれる」という組み合わせなので、query系でもエラーキュー確認を省略しないこと。

## 5. `*OPT?` は送信していない(意図的)

MHO900プログラミングガイドのIEEE488.2章(3.12)に `*OPT?` は存在しない(`*IDN? *RST *CLS *ESE *ESR? *OPC *SRE *STB? *WAI *TST?` の10個のみ)。DHO800/900・DS1000Zの各ガイドにも存在しないことを確認済み。未定義ヘッダの送信はSCPIサーバーを沈黙させるため送信しない。オプション照会は `:SYSTem:OPTion:STATus?` のみを使う。

## 6. 実装への反映(Phase 4 PR A)

- `option_query: ":SYSTem:OPTion:STATus?"` + `option_types`(ガイド記載11トークン)を `mho98.yaml` のdialectへ(本記録が実機検証エビデンス)
- generic プロファイルには宣言しない(`:SYSTem:OPTion:*` はMHO900専用。DHO800/900には存在しない)
- ライセンス適用後の再検証(before/after)は Phase 4 完了時に別記録として追記する
